# Карта рук ANTR

Интерактивная карта суставов кисти, которые видит сконвертированная Quest-игра на
**Samsung Galaxy XR**. В одном 3D-виде совмещены живые суставы `XR_EXT_hand_tracking` рантайма
Galaxy XR, bind-поза, которую адаптер [overport-galaxyxr](https://github.com/4uva4ek/overport-galaxyxr)
отдаёт OVRPlugin, скелет покоя, который реально получает игра, и эталонная поза покоя Quest.
Слой правки позволяет подвинуть суставы руками и выгрузить таблицу, которую адаптер использует
при `--hand-bind=edited`.

Один HTML-файл, без сборщиков. Python 3 (только стандартная библиотека) пересобирает данные из
захвата logcat. Автор: **4uva4ek**.

## Состав

| Файл | Назначение |
| --- | --- |
| `ANTR-hand-map.html` | Карта со встроенными данными. Открыть в браузере, больше ничего не нужно. |
| `ANTR-hand-map.template.html` | Страница без данных; `__DATA__` заменяется на JSON. |
| `ANTR-hand-map-data.json` | Слои суставов из `samples/hand-diag5-lines.txt` и `OVRSkeletonData.cs`. |
| `ANTR-extract-hand-map.py` | Строит JSON из выжимки `HAND`-строк logcat (и, по желанию, позы покоя Meta). |
| `ANTR-build-hand-map.py` | Встраивает JSON в шаблон. |
| `ANTR-update-edited-table.py` | Записывает выгруженные правки в таблицу `kEditedBind` в исходниках адаптера. |
| `samples/hand-diag5-lines.txt` | Эталонный захват: Job Simulator 1.4.0.6515 на SM-I610 (I610UEU2AZF3), 2026-10-14. |
| `samples/hand-edits-left-20261014.json` | Выгрузка, из которой собрана встроенная таблица `handbind=edited`. |

## 1. Откуда брать логи

Данные пишет **диагностическая сборка** адаптера overport-galaxyxr. Релизный адаптер суставы
не логирует: из игры, сконвертированной релизным CLI, извлекать нечего.

### 1.1 Собрать адаптер с диагностикой рук

В клоне overport-galaxyxr (Linux или WSL, Android NDK r29 в `ANDROID_NDK_HOME`):

```bash
GXR_HAND_DIAGNOSTICS=1 bash native/galaxyxr/build.sh
./gradlew :overportcli:shadowJar
```

Первая команда компилирует `native/galaxyxr/policy.cpp` с `-DGXR_HAND_DIAGNOSTICS` и кладёт
`libopenxr_loader_generic.bin` в ресурсы CLI; вторая собирает jar CLI (`overportcli/build/libs/`).
Диагностическая сборка добавляет к обычной работе адаптера:

- `HAND create` / `HAND locate` / `HAND joint`: каждый результат `xrLocateHandJointsEXT`, не чаще
  одного образца на трекер в 2 секунды, все 26 суставов (позиция, ориентация, радиус, флаги) в
  мировых координатах.
- `HAND mesh` / `HAND bind`: описание `XR_FB_hand_tracking_mesh` после достройки адаптером
  (26 суставов с родителями, радиусами и bind-позами в корневой системе OVR).
- `HAND ovrp skeleton` / `skelraw` / `skelbone`: скелет покоя `ovrp_GetSkeleton2`, прочитанный у
  OVRPlugin 1.88 ровно в том виде, в каком его получает игра. Наблюдатель только читает и
  существует только в диагностической сборке.

### 1.2 Сконвертировать и установить игру

```bash
java -jar overport-galaxyxr-<version>-cli.jar patch --input=game.apk --target=galaxyxr --hands=on
adb install -r <output>.apk
```

`--hands=on` заставляет игру запросить разрешение Android XR `HAND_TRACKING` при запуске; без
разрешения рантайм никогда не отдаёт активные суставы. Другие опции рук, влияющие на захват:
`--hand-mesh=fix|runtime`, `--hand-frames=meta|runtime`, `--hand-bind=rebuild|edited`.
Запишите, с какими опциями конвертировали: слои `bind` и `ovrp` показывают их эффект. CLI
записывает выбранные опции в `lib/arm64-v8a/liboverport.galaxyxr.config.so` внутри APK
(строки `handmesh=`, `handframes=`, `handbind=`); оттуда их читает адаптер.

Это обычная установка приложения. Ничего на гарнитуре, кроме сконвертированной игры, не меняется.

### 1.3 Снять logcat

Пишите тег адаптера в файл на протяжении всей сессии, чтобы кольцевой буфер не переполнился
(полная сессия — это десятки мегабайт logcat):

```bash
adb logcat -c
adb logcat -v threadtime -s OverportGXR > overport-logcat.txt
```

Затем в гарнитуре:

1. Запустите сконвертированную игру и выдайте разрешение на трекинг рук, когда спросит.
2. Держите обе руки в поле зрения, чтобы они трекались. Игра запрашивает меш рук (`HAND mesh`,
   `HAND bind`) при первом появлении трекинга; скелет OVRPlugin (`HAND ovrp`) логируется один
   раз на трекер сразу после этого.
3. Подержите несколько секунд раскрытые ладони с прямыми, разведёнными пальцами. Живые образцы
   пишутся каждые 2 секунды на руку; карта по умолчанию выбирает образец с самыми прямыми
   указательным и средним пальцами, а ползунок показывает все.
4. Остановите захват `Ctrl+C`.

Выделите строки `HAND` (экстрактор игнорирует все остальные строки, так что можно подать и полный
logcat, просто медленнее):

```bash
grep "OverportGXR: HAND" overport-logcat.txt > hand-lines.txt
```

PowerShell:

```powershell
Select-String -Path overport-logcat.txt -Pattern "OverportGXR: HAND" | ForEach-Object Line | Set-Content -Encoding utf8 hand-lines.txt
```

Пригодная выжимка содержит на каждую руку: `HAND locate ... result=0 active=1` и за ним 26 строк
`HAND joint`, одну `HAND mesh ... fixed=1` и за ней 26 строк `HAND bind`, а также строки
`HAND ovrp skelraw`. Полный пример: `samples/hand-diag5-lines.txt`.

### 1.4 Эталонная поза покоя Quest (по желанию)

Слой `meta` берётся из `OVRSkeletonData.cs` Oculus Integration для Unity
(`Assets/Oculus/Interaction/Runtime/Scripts/Input/OVRIntegration/OVRSkeletonData.cs` в любом
Unity-проекте с Meta XR Interaction SDK). Это код Meta, в репозиторий он не включён; передайте
свою копию через `--meta`. Без него слоя `meta` просто не будет. Встроенный
`ANTR-hand-map-data.json` уже содержит производную позу покоя.

## 2. Собрать карту

```bash
python -I ANTR-extract-hand-map.py hand-lines.txt --meta OVRSkeletonData.cs
python -I ANTR-build-hand-map.py
```

Первая команда пишет `ANTR-hand-map-data.json` рядом со скриптами (`--out` меняет путь) и
печатает, сколько живых образцов и костей у каждой стороны. Вторая встраивает его в
`ANTR-hand-map.html`. Оба скрипта принимают явные пути:
`ANTR-build-hand-map.py [data.json] [out.html]`.

Пересобрать встроенную карту из эталонного захвата:

```bash
python -I ANTR-extract-hand-map.py samples/hand-diag5-lines.txt --meta /путь/к/OVRSkeletonData.cs
python -I ANTR-build-hand-map.py
```

## 3. Как пользоваться картой

Откройте `ANTR-hand-map.html`. Всё рисуется в **системе координат запястья OpenXR** выбранной
руки: запястье в начале координат, **−Z к пальцам**, **+Y из тыльной стороны кисти**, +X к большому
пальцу на левой руке. Сетка 1 см лежит в плоскости текущего вида.

**Рука**: кнопки «Левая» / «Правая» в шапке переключают сторону. Слои, образцы и правки хранятся
для каждой стороны отдельно.

**Слои** (флажки, цвета):

- `live` (синий): суставы рантайма из выбранного образца, перенесённые в систему запястья.
- `bind` (красный): достроенная bind-поза `XR_FB_hand_tracking_mesh`, которую возвращает адаптер;
  именно из неё OVRPlugin делает скелет игры.
- `ovrp` (фиолетовый): скелет покоя `ovrp_GetSkeleton2`, как его получает игра (24 кости OVR; в
  OVR нет пястных костей указательного, среднего и безымянного пальцев).
- `meta` (зелёный): эталонная поза покоя Quest из `OVRSkeletonData.cs`.
- `правка` (янтарный): ваша редактируемая копия одного из слоёв.

**Живой образец**: ползунок перебирает записанные образцы выбранной руки, показывает время и
углы сгиба указательного и среднего пальцев. **Опора запястья** выбирает ориентацию, относительно
которой всё размещается: «выровненная» — система запястья после `alignHandFrames` адаптера
(то, что даёт `--hand-frames=meta`), «сырая Galaxy» — нетронутая ориентация запястья Galaxy XR.

**Вид**: четыре камеры (тыл кисти, ладонь, сбоку со стороны большого пальца, с кончиков).
Тяните пустой фон, чтобы вращать, колесо — масштаб. Флажки включают имена суставов, длины костей
в миллиметрах и сетку. **Оси суставов** рисуют локальные оси X (красная), Y (зелёная), Z (синяя)
одного слоя; соглашение адаптера: +Z вдоль кости к родителю, +Y — крен.

При наведении на точку выводятся её слой, имя и координаты в миллиметрах.

### 3.1 Правка bind-позы

1. Выберите **источник** (`bind`, `live`, `ovrp` или `meta`) и нажмите **«Скопировать в правку»**.
   Слой правки получает независимую копию с позициями, ориентациями и родителями.
2. Включите **режим правки**. Перетаскивание янтарной точки двигает её в плоскости экрана, поэтому
   выберите вид, в котором видны две нужные оси. Оси автоматически переключаются на слой правки.
3. Клик по точке открывает её редактор: поля X/Y/Z в миллиметрах (со смещением от источника) и
   кнопки поворота вокруг собственных осей сустава шагом 1° и 5°: **X** — сгиб, **Y** —
   разведение, **Z** — крен вокруг кости. С включённым «вращать вместе с дочерними точками» всё
   поддерево поворачивается как скелет; без него меняется только ориентация этого сустава, а его
   позиция фиксируется.
4. Ориентации сдвинутых суставов пересчитываются из новых позиций по правилу `boneFrame` адаптера
   с сохранением крена (+Y) исходного сустава, так что у выгруженных кадров +Z всегда вдоль кости.
5. **«Сбросить»** возвращает слой к источнику. Правки хранятся в `localStorage` браузера для каждой
   стороны, пока вы их не сбросите или не скопируете слой заново.

### 3.2 Выгрузка

**«Собрать JSON правок»** заполняет текстовое поле (**«Копировать»** кладёт в буфер обмена).
Для каждого сустава:

| Поле | Значение |
| --- | --- |
| `name` | Имя сустава OpenXR (`palm`, `wrist`, `th_meta` … `lt_tip`). |
| `p_mm` | Позиция в системе запястья, миллиметры. |
| `delta_mm` | Смещение от исходного слоя. |
| `rot_deg` | Накопленный поворот кнопками (X, Y, Z). |
| `q_xyzw` | Ориентация в системе запястья по правилу `boneFrame`. |
| `p_ovr_root`, `q_ovr_root` | Та же поза, повёрнутая на `C_hand` в корневую систему OVR, то есть в раскладку bind-таблицы адаптера. |

`C_hand` — константа на руку, которой OVRPlugin 1.88 преобразует bind-позы FB:
левая `(0.7071, 0, −0.7071, 0)`, правая `(0, 0.7071, 0, 0.7071)` (x, y, z, w).

## 4. Как вернуть правки в адаптер

В адаптере есть встроенная таблица `kEditedBind` в `native/galaxyxr/hand_tracking.inc`. В ней
**левая** рука в системе запястья (метры, xyzw); правая получается зеркалированием X, а все
ориентации адаптер пересобирает из позиций и крена +Y каждой строки. Игра, сконвертированная с
`--hand-bind=edited`, использует эту таблицу вместо bind-позы, выведенной из данных рантайма.

1. Правьте **левую** руку и выгрузите её (раздел 3.2). Правую выгружайте только для сравнения.
2. Запишите таблицу:

   ```bash
   python -I ANTR-update-edited-table.py export.json /путь/к/overport-galaxyxr/native/galaxyxr/hand_tracking.inc
   ```

   Заменяются только 26 строк таблицы; повторный запуск ничего не меняет.
3. Пересоберите адаптер (релиз, без `GXR_HAND_DIAGNOSTICS`), прогоните host-тест и пересоберите CLI:

   ```bash
   bash native/galaxyxr/build.sh
   g++ -std=c++17 -O2 -Wall -Wextra -Werror -Wno-missing-field-initializers -Inative/galaxyxr/include native/galaxyxr/test_hand_tracking.cpp -ldl -pthread -o native/galaxyxr/build/test_hand_tracking && native/galaxyxr/build/test_hand_tracking
   ./gradlew :overportcli:shadowJar
   ```

4. Сконвертируйте игру с `--hand-bind=edited`, установите и проверьте руки в игре. Чтобы увидеть
   результат на карте, сконвертируйте диагностическим адаптером и снимите лог заново (раздел 1):
   новые слои `bind` и `ovrp` покажут, что теперь получает игра.

`samples/hand-edits-left-20261014.json` — выгрузка, из которой собрана текущая встроенная таблица.

## 5. Формат файла данных

`ANTR-hand-map-data.json`: `source` (имена входных файлов), `xrNames`/`xrParents` (26 суставов
OpenXR и их родители), `ovrNames` (24 кости OVR), `ovrToXr` (индекс кости OVR → сустав OpenXR)
и `sides["0"|"1"]` с полями:

- `live[]`: `time`, `indexCurl`, `middleCurl` и 26 `joints` (`r` радиус, `p`, `q` сырая,
  `qAligned` после `alignHandFrames`), мировые координаты.
- `bind[]`: 26 суставов с `parent`, `r`, `pOvr`/`qOvr` (корневая система OVR) и `p`/`q` (система запястья).
- `ovrp[]`, `meta[]`: 24 кости с `id`/`name`, `parent`, `xr` (соответствующий сустав OpenXR),
  `pLocal`/`qLocal` (относительно родителя), `pOvr`/`qOvr` (относительно корня) и `p`/`q` (система запястья).

Позиции в метрах, кватернионы (x, y, z, w).
